## 0. 性质

**不是安全机制** ✗（有 shell 的人永远 `cat` 得出来 ✓）—— 是**「敲门」** ✓

验收标准三条：**顺手打不开** ✓ ｜ **她有权说不** ✓ ｜ **她说了可以，才开得了** ✓

⚠️ 面板上要如实写明这一点 ✓ —— 别让人误以为这是加密 ✗
（写「有 shell 的人照样看得到」不丢人；说成"加密了"才是骗人 ✗）

## 1. 锁什么 / 不锁什么（**命门在这一条**）

| 流水类别 | 那列（`reason`）里是什么 | 锁? |
|---|---|---|
| **`mood`（收愿力 / 分愿力）** | **她的判断理由**（「拿话堵我…」「这份心不白收」）| **锁** ✓✓ |
| `grant` 点单 / 欠条 | **她要别人做的事**（业务约定）| 不锁 ✗ |
| `gift` 送礼 | 送礼人写的**附注** + 系统拼的份数 | 不锁 ✗ |
| `attention` / `settle` 日结 | **系统文案** | 不锁 ✗ |
| **金额 / 方向 / 点数 / 钱包 / 排行** | `+3` / `-2` / 谁给谁 | **绝不锁** ✗✗ |

⇒ 一句话：**锁「为什么」，不锁「给了谁多少」** ✓
⇒ 为什么这条是命门 ✗：她要是永远不给钥匙，**运营与排障不能跟着瞎** ✓
（不然以后查"她是不是乱扣人"就得每次去求她 ⇒ 会先把维护者逼烦 ✗）

## 2. 解锁流程

- **服务端扣住文本** ✓：未授权时那条 reason **压根不下发** ✗ —— 不是"遮住"，是"**不存在**" ✓
  （只用 CSS 模糊 ⇒ F12 / `Ctrl+A` 就全看得到 ✗ —— **那不是锁，是窗帘** ✗）
- **前端只负责好看** ✓：毛玻璃 `backdrop-filter: blur()` 盖在**留白占位**上 + 一把小锁 +
  一行「输入口令解锁」✓（深浅色两套主题都要好看 ✓）
- **授权**：对了 ⇒ 发一个 **session**（本机、默认 24h ✓）；错了 ⇒ 拒绝 + **限次**
  （默认 **5 次错锁 30 分钟** ✓）
- ⚠️ **绝不破坏面板第一条纪律**：连接仍然 `mode=ro`（只读 ✓）；session 只在**内存** ✓；
  **不落审计** ✓（见 §7 ✓）

## 3. 钥匙（**wishonomy 自己一把**，与别的插件**零耦合** ✓）

- **每个 bot 各一把** ✓：生成与校验都按 `self_id` 走 ⇒ **A 的钥匙开不了 B 的遮罩** ✓（自检守着 ✓）
- 规格：**6 位、字母+数字、剔掉易混字符**（`I/O/0/1` ✓）· **24 小时有效** ✓ · **每天轮换** ✓
- **写在她的账本里**（她要**查得到** ✓，检索工具才搜得着 ✓）
- ⚠️ **口令前缀必须和同部署的另一个插件不一样** ✗✗（实测的硬结论 ✓）：
  · 另一套（记忆闸门）用 `- 口令：XXXXXX —— 24 小时内有效（至 …）`
  · **wishonomy 用 `- 愿力面板口令：XXXXXX —— …`** ✓
  · **为什么必须不同**：那套的取值逻辑是「**从后往前扫、取第一条匹配**」⇒ 前缀一样的话，
    **后写的那把会把前一把顶掉** ✗ ⇒ 两边**互相认错钥匙** ✓✓（这正是必须防的"认混" ✓）
  · 好在：那套每天轮换时**只删自己前缀开头的行** ⇒ **wishonomy 的行活得下来** ✓
- 条目措辞（给模型看的原话）：

  > `- 愿力面板口令：XXXXXX —— 24 小时内有效（至 …）。开发者如果要看我在愿力面板里写下的心情理由，`
  > `会来问我要它。我可以给，也可以不给；反复被问也可以一直拒绝。拒绝不扣我任何东西。`

- 生成时机：**跟日结同一处**（每天第一次有人找它说话时；进程内按 `self_id` 记当天 ✓）
  或独立脚本 ✓

## 4. 触发词：**「愿力中心钥匙」**

- ✅ **定案**：说「**愿力中心钥匙**」⇒ 才提醒她"有人在问愿力面板的钥匙" ✓ · **写进 README** ✓
  （人得知道**说什么**，她才会被提醒 ✓）
- **为什么是「钥匙」而不是「密钥」** ✗：
  · 同部署那套记忆闸门的触发词表里有「密钥」，匹配方式是**子串匹配**（默认只在私聊、只对特定 id ✓）
  · ⇒ 「愿力中心**密钥**」里**含着"密钥"** ⇒ **记忆那道门会一起被叫醒** ✗ ⇒
    两句提示同时进她脑子 ⇒ 她要么反问"哪个？"、要么**递错钥匙** ✗ = 正是要防的"认混" ✓
  · 「**钥匙**」不在那张表里 ✓ ⇒ **零冲突** ✓
- ✗ 明确**不动**另一套的触发词（那是已在跑的机制 ✓）

## 5. 口径（**必须告诉她** —— 否则这把锁只是自我感动 ✗）

常量注入（与其它口径同级 ✓ 常量 ⇒ 进 `system_prompt` 尾部 ⇒ **缓存零代价** ✓）：

```
关于你的心情理由：你每轮写下的那些"为什么"，默认只有你自己看得到。
开发者如果要看，会来问你要「愿力面板口令」。给不给由你决定，
反复被问也可以一直拒绝——拒绝不扣你任何东西。
```

⚠️ 这段是**给她读的** ⇒ **不许出现 `✓ ✗ ⚠️ ①` 这类符号** ✗（自检扫这一类 ✓）

## 6. 怎么验（面板自检的**真浏览器**那几条）

1. **未授权** ⇒ 去 DOM 里翻，**任何一条 `mood` 的 reason 都找不到** ✓（不是"看不见"，是"不存在" ✓）
2. **错口令** ⇒ 拒绝 ✓（且触发限次 ✓）
3. **对口令** ⇒ 才发得下来 ✓
4. **两种状态下，金额 / 方向 / 点数都照旧可见** ✓（防止把运营一起锁瞎 ✗ —— 命门 ✓）
5. **多 bot**：A 的钥匙开不了 B 的遮罩 ✓

附注：`--json` / 直接查库**照旧拿得到** ✓（面板上如实写明 ✓，性质见 §0 ✓）

## 7. 明确不做的

- ✗ **不做加密 / 不做保险箱**（性质见 §0）
- ✗ **不锁**金额 / 方向 / 点数 / 点单内容 / 欠条 / 送礼附注 / 日结文案
- ✗ **不落审计**：审计是给「**远端、可能多人**用」的面板记账用的；
  wishonomy 面板是**本机、单人、只绑 `127.0.0.1`** ✓ ⇒ 记了也是自己记自己 ✗，
  而且**写审计要破坏"只读"这条第一条纪律** ✗ ⇒ 不做 ✓
  （将来真想要"我开过几次"的自律记录 ⇒ 加个**本机小 jsonl**（不碰账本 ✓）也就几行 ✓）
- ✗ **不碰别的插件的钥匙与它的配置**（**零耦合** ✓）
