# 路线图与边界

## 阶段

| 阶段 | 内容 | 状态 |
|---|---|---|
| **P1** | 仓库骨架 · SQLite 账本 + `user_version` 迁移 · 幂等 · 身份闸门 · `wish_check` / `wish_mood` / `wish_gift` / `wish_audit` · 自检 | ✅ 已做 |
| **P2** | 发行侧护栏补齐：全局日发行熔断 · 备份白名单 · 配置热重载核对 | ⏳ |
| **P3** | **点单**：`wish_grant`（愿力直接到账 + 记 IOU）· `wish_iou_settle` · `refund`（只在那笔对方没动过时成功） | ⏳ |
| **P4** | 信誉分动作 · 排行 `wish_leaderboard` · 对账报表细化 | ⏳ |
| **P5** | 部署 + 真机冒烟（真群小样验证；重启前先在对话里打招呼 ✓） | ⏳ |
| **P6** | 只读账本页（可选，只给运营看） | ⏳ |

## 边界（不做的事）

- ❌ **不做"用户直接调"的写入接口** —— 账本只由 bot 的工具改
- ❌ **不做余额状态尾巴**（每条消息后面挂"余额：12"）—— 那会把聊天变成游戏 UI
- ❌ **不做充值 / 提现 / 真实货币锚定**
- ❌ **不做用户之间的互转**（P2P）—— 流水结构支持，但开关不开
- ❌ **不注入 prompt**（见 `ARCHITECTURE.md` §5）

## 已知上限（有意留着的）

- 账户名缓存是**进程内**的（重启后按昵称认人会短暂退化，直到对方再说一次话）
  `ponytail:` 不落盘是故意的 —— 它是易失的旁路信息，不值得为它多一张表
- 单 worker 线程池：账本安全优先；真成瓶颈再改每账户锁
- `iou` / `credit_event` 表 P1 只建表，动作在 P3/P4
